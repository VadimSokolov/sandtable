## 1. Executive Summary & Operational Objective

### The Strategic Value of `mission_viewer_v2`
Across Phases 1, 2, and 3, SandTable implemented seven core convoy capabilities in Python. While specialized standalone tools (`route_dashboard.html`, `cargo_dashboard.html`, `convoy_results.html`) were generated to validate specific subsystems in isolation, commanders and analysts currently lack a **single unified operational console**.

`mission_viewer_v2` unifies all seven capabilities into a single, high-fidelity visual replay environment. This creates the essential visual testbench needed before executing **Phase 4 (Issue #12: Security Vehicles & Contact Reaction)**, where escorts maneuver, lay down suppressive fire, and cargo elements execute a herringbone defense posture under live ambush.

## 4. Technical Implementation Phases

### Phase 1: Replay Engine Extension (`replay.py` & Scenario Presets)
1. Verify that `sandtable.replay.record_trace` exports all required per-frame arrays:
   - Entity coordinates `(x, y)`, `alive`, `seen`, `cargo_delivered`, `progress` ($s$).
   - Static topology: `world.buildings`, `world.building_boxes`, `world.street_graph`, `world.route`.
   - Entity static roles: `convoy_role`, `cargo` capacity, `domain`, `side`.
2. Curate 4 contrasting mission traces showcasing all capabilities:
   - **Preset 1 (Urban Grid & Occlusion)**: 6 vehicles navigating an urban block grid with 4 buildings, 90-degree doglegs, and blind-corner LOS transitions.
   - **Preset 2 (MSR Convoy Ambush & Escort Defense)**: 15-vehicle column ($1 \times 3 \times 5$) on an open Main Supply Route with armed escorts engaging Red ambushes, demonstrating cargo protection.
   - **Preset 3 (Doctrinal Headway & Spacing Contrast)**: Comparison of open-column dispersed march ($\Delta t = 6.0\text{s}$) vs closed-column tight march ($\Delta t = 2.0\text{s}$).
   - **Preset 4 (Arc-Length Stationing vs Corner-Cutting)**: Dogleg route showing how 1D stationing keeps vehicles centered in lane compared to Euclidean baseline.

### Phase 2: Standalone Dashboard Generator (`tools/make_mission_viewer_v2.py`)
1. Create a Python generator that loads scenarios, records traces via `record_trace`, packages the data into compact JSON, and embeds it into a standalone HTML file:
   - Output: `report/viz/mission_viewer_v2.html` (and `report/viz/_artifact_body_v2.html`).
2. Implement robust subsampling and compression so the standalone file loads in under 2 seconds.

### Phase 3: High-Performance Canvas Renderer
1. Multi-layer rendering pipeline on HTML5 Canvas:
   - **Layer 0**: Background terrain grid, cover/concealment rasters.
   - **Layer 1**: Street graph corridors and building blocks with architectural styling.
   - **Layer 2**: Surveyed route polyline with numbered waypoints.
   - **Layer 3**: Line-of-sight sightlines between convoy vehicles (cyan for clear, crimson for building-occluded).
   - **Layer 4**: Combat engagement tracers, weapons range circles, and kill markers.
   - **Layer 5**: Vehicle hulls with doctrinal role glyphs, headings, and ID badges.
2. Auto-scaling and smooth zoom/pan navigation.

### Phase 4: Telemetry Rail & Hierarchy Sidebar
1. **Dynamic KPI Ribbon**: Updates synchronously on every animation frame:
   - Cargo delivered tonnage, in-transit tonnage, destroyed tonnage, and throughput rate.
   - Instantaneous column pace, vehicle headway, and column length.
   - Cornering lateral deviation and route completion percentage.
2. **Hierarchy Tree & Vehicle Manifest**:
   - Interactive vehicle list sorted by march unit and column rank.
   - Click-to-focus: clicking any vehicle highlights it on the canvas and opens its telemetry card.
3. **Tactical Event Log**:
   - Stream of timestamped mission milestones (ambushes, detections, kills, deliveries, corner occlusions).

### Phase 5: Cross-Tool Navigation Integration
1. Update top navigation headers across existing dashboards:
   - [`route_dashboard.html`](file:///Users/markfahim/Work/GRA%20GM/sandtable/report/viz/route_dashboard.html)
   - [`cargo_dashboard.html`](file:///Users/markfahim/Work/GRA%20GM/sandtable/report/viz/cargo_dashboard.html)

## 5. Verification & Acceptance Criteria

1. **Self-Contained Standalone Artifact**:
   - `report/viz/mission_viewer_v2.html` opens directly via local HTTP server without external network dependencies.
2. **Comprehensive Capability Integration**:
   - Hierarchy (March units/serials/roles) visible and interactive.
   - Cargo delivered/loss metrics update accurately in real time.
   - Pace, time gap, and column length reflect ATP 4-16 doctrine.
   - Route polyline and stationing progress displayed without corner-cutting.
   - Building blocks and dynamic line-of-sight occlusion clearly rendered.
3. **Playback Performance**:
   - Smooth 60 FPS animation playback with responsive scrubbing.
4. **Code Quality & Test Suite**:
   - Clean linter (`ruff check .` with zero errors).
   - Full test suite passes without regressions (`pytest tests/`).
5. **Visual Validation**:
   - Verified via browser subagent with captured screenshot artifacts.
